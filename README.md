# handson-2026-git 運営用

受講者ブランチの監視と、コンフリクト演習の仕込みをするスクリプトです。
`main` とは履歴を共有しない orphan ブランチ `admin` に置いています。

Git Bash で動きます。

## セットアップ

```bash
git clone -b admin git@github.com:cpslab/handson-2026-git.git handson-2026-admin
cd handson-2026-admin
# 名簿 (任意)。1 行に 1 人の学籍番号。あれば未 push の人も一覧に出る
vi students.txt
```

初回実行時に `.work/` へ作業用の clone が作られます。`.work/`、`students.txt`、`injected.tsv` は commit されません。

## 投影用ページ

```bash
./serve.sh              # http://localhost:8000 を開く
PORT=8080 ./serve.sh    # ポートを変える場合
```

5 秒ごとに自動で更新され、状態が変わったカードは光ります。

- 右上のボタンか `1` / `2` キーで「進捗」と「自己紹介」を切り替えます。`http://localhost:8000/#intro` を開くと最初から自己紹介を表示します
- 自己紹介は各ブランチの `学籍番号.md` の今の中身から、`名前:` と `一言:` を大きく表示し、ほかの `項目: 値` の行や自由な文もそのまま並べます
- `C` キーで各自のファイルの中身 (進捗の画面)、`F` キーで全画面表示を切り替えます
判定は `monitor.sh` と同じです。Python 3 が必要です（標準ライブラリのみ）。サーバーは自分の PC からしか開けません（127.0.0.1 で待ち受け）。

## 受講者に配るテンプレート

`main` の `template.md` をコピーして `学籍番号.md` を作ってもらいます。

ファイル名は **ブランチ名と同じ** `学籍番号.md`（例: ブランチ `24FI001` なら `24FI001.md`）。運営が先に `ブランチ名.md` を作るので、大文字小文字までブランチ名と揃えないとコンフリクトが起きません。監視側はブランチ名・ファイル名・名簿の大文字小文字を区別せずに判定し、一覧では大文字で表示します。

```markdown
# 24FI001

- 名前: 山田太郎
- 趣味: 自転車
- 好きなこと: カレーを食べること
- 一言: よろしくお願いします
```

## 当日の流れ

事前に運営は `./inject-conflict.sh -w 5` と `./serve.sh` を起動しておきます。

1. 受講者: `git switch -c 学籍番号` → `git push -u origin 学籍番号`（ブランチだけ push）
2. 運営（自動）: `inject-conflict.sh -w` が新しいブランチを見つけ、テンプレートの「一言:」に運営の文言を入れた `ブランチ名.md` を先に作って push する
3. 受講者: `template.md` をコピーして `学籍番号.md` を書き、add → commit → push → **reject される**
4. 受講者: `git pull --no-rebase` → コンフリクト（運営と受講者が同じファイルを別々に作ったので、中身に関係なく必ず起きる）→ 解決して commit → push
5. 運営: 投影ページで全員が「解決」になったか確認する

手順 4 は、受講者の Git の設定によっては素の `git pull` が「divergent branches」で止まります。
手順書には `git pull --no-rebase` と書くか、最初に `git config --global pull.rebase false` を打ってもらってください。

### 間に合わなかった人
運営が先回りする前に `学籍番号.md` まで push してしまった人（`PUSHED`）には、自動モードは何もしません。
`./inject-conflict.sh 学籍番号` を実行すると、その人の「一言:」の行を書き換えます。「一言:」の行がなければ「好きなこと」→「趣味」→「名前」の順に、最初に見つかった行を書き換えます（`config.sh` の `TARGET_KEYS` で変更可）。
この場合は同じ行を書き換えないとコンフリクトしないので、出力（例: `23FI084.md の「趣味」を書き換え`）を見て、その人に「commit してから pull せずに push」までの手順と書き換える行を伝えてください。

## monitor.sh の STATUS

| STATUS | 意味 |
| --- | --- |
| `NO_BRANCH` | ブランチがまだない（名簿にいる人だけ表示） |
| `BRANCH_ONLY` | ブランチだけ push された。自動モードがすぐ仕込む |
| `NO_FILE` | 受講者の `学籍番号.md` がない。`template.md` を直接編集した、ファイル名を間違えたなど |
| `PUSHED` | 運営より先に `学籍番号.md` まで push された。「間に合わなかった人」を参照 |
| `INJECTED` | 運営が仕込んだ。受講者の対応待ち |
| `RESOLVED` | 運営コミットの後に受講者が push した |
| `MARKER_LEFT` | `<<<<<<<` などのマーカーが残ったまま push された |
| `FORCE_PUSHED` | 運営のコミットが履歴から消えている（`push -f` された） |

一覧の下には、学籍番号の形式に合わないブランチ（打ち間違い）と、名簿にない学籍番号も表示されます。

## 設定

文言や学籍番号の形式は `config.sh` で変えられます。別のリポジトリで試すときは `REPO_URL=/path/to/repo.git ./monitor.sh` のように実行します。

`inject-conflict.sh` は書き換え済みのブランチを飛ばすので、何度実行しても大丈夫です。push が間に合わず遅れて push した人がいたら、もう一度実行してください。
